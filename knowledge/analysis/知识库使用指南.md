# 综述/知识库使用指南

## 摘要

本地《原神》知识库四个前缀（原神wiki 19240 / 原学视频 74 / 日月全事 22 / 考证 10）各是什么、条数为何与来源自述不一致、基于 FTS5 trigram 的检索机制与最有效搜法、四类典型检索示例、本库边界与三个零覆盖主题、以及基于 manifest 文件的回滚方式。

## 正文

【一、四个前缀各是什么】
· 原神wiki/ ——19240 条。biligame《原神》WIKI 全站正文离线副本：原站主命名空间 51,347 页，排除 32,122 个 Data:Map 机器数据页后的全部正文，一条未漏。每条＝信息框（键值对）＋正文（技能、属性表、材料、攻略）＋来源链接，原始 wikitext 由确定性程序清洗为纯文本，未经 LLM 改写。性质：全库唯一的原文层。（注：条目「原神wiki/总览与用法」自称 19239 条，本次实测 19240 条，差 1。）
· 原学视频/ ——74 条。62 个 B站「原学」视频（4 位 UP 主：写书的王紫 52、念绛河 8、tnmy83 1、蒸汽鸟报_official 1；816 分钟；全部无 CC 字幕，故自行 SenseVoice 转写）。每条＝核心论点＋关键论据＋涉及的原神设定＋涉及的现实原型＋结论与推论＋【存疑或作者自述推测】；另有 4 条跨视频主题总表（原学视频/主题·…）与 1 条总索引。性质：二手推断层（原型学、命名学、玩家建模）。注意 74 条 ≠ 62 个视频：61 条首批单集＋1 条补录＋5 条主题／索引＋7 条后续补录单集（BV11Wus6KEYi、BV1G8wtzWEFo、BV1xETy6WEDb、BV13gddBJEZ7、BV17Eu56fEBG、BV1K9FHzdEXj、BV1NYopBEETS），后 7 个 BV 不在 README 记录的 62 个视频清单内。
· 日月全事/ ——22 条。《日月全事》原神世界观手册（genshinlore.cn）网站版逐章整理，作者诗漱。手册自述「内容几乎全部源于游戏内的文案，尤其是圣遗物、武器、书籍中的背景故事」，带引用编号与不确定性标注。22 条覆盖：前言与阅读顺序、编者后记与方法论、提瓦特通史、时间线年表、降临者、天理与法则、魔神与七执政、光界与龙族、元素使用、深渊与虚界、设施与地脉、星空与命之座、坎瑞亚历史、蒙德／璃月／稻妻／须弥／枫丹／纳塔／至冬七国国别史、剧情观看顺序、趣闻与杂谈。性质：世界观主干整合层。
· 考证/ ——10 条，已完成的多来源冲突考证：天理与法涅斯之名、葬火之战的年代、提瓦特尺度与虚假之天、神之眼的发放者、三月一星与少女／伊斯塔露、散兵与刀匠事件、花神与慈树王的魔神名、坎瑞亚的原型与《裴伦埃里》、兹白琅玕与三尸神、尼伯龙根与第二王座。性质：分歧地图＋证据评级＋少数「可直接判定」的结论。

【二、怎么检索最有效】
底层是 SQLite FTS5：CREATE VIRTUAL TABLE fts USING fts5(id UNINDEXED, title, problem, solution, tags, tokenize='trigram')。五条实测规则：
1. trigram 是子串匹配，不是分词匹配：查询串被当成一个整串短语。
2. 2 字查询走 LIKE 全表扫描（实测约 130~150 ms），3 字以上走 FTS（1~8 ms）。2 字能搜，但别用 2 字的通用词。
3. 多词空格查询必然查不到。实测 kb_search("魔神 第二王座") 返回「知识库中没有匹配」（3 ms），而 kb_search("第二王座") 命中 2 条。所以必须把多词拆开分别搜，或改成一个连续子串。
4. 一次最多返回 50 条，且只给 id／标题／tags／摘要；正文必须再用 kb_get 取全文。
5. 优先搜「游戏内专名或原句片段」，不要搜概念词：搜「慈水怒涛之翼」比搜「魔神」精确得多，搜「第二王座」比搜「尼伯龙根」更贴近分歧点。
按前缀浏览：搜「主题·」得 4 条跨视频总表；搜「总索引」得视频库说明；搜「总览与用法」得 wiki 库说明。

【三、典型检索示例】
（a）查角色原型。搜「埃斯科菲耶」→ 原学视频/爱可菲原型：法餐厨皇埃斯科菲耶考据 ＋ 原神wiki/爱可菲；搜「紫微斗数」→ 原学视频/璃月七星的紫微斗数原型 ＋ 原学视频/主题·命名取材规律总表。想一次看全就搜「主题·」取《命名取材规律总表》（坎瑞亚→北欧神话＋瓦格纳、至冬→斯拉夫神话＋沙俄、蒙德→德语文学、须弥→阿拉伯／伊斯兰、纳塔→约鲁巴／祖鲁、璃月→中国典籍、稻妻→日本战国、枫丹→法国美好年代）。流程：先搜角色名拿单集条目 → 读【存疑或作者自述推测】 → 再搜原型专名（「逸周书」「云笈七签」）交叉验证到考证条目。
（b）查某国历史。搜「璃月历史」→ 日月全事/璃月历史 ＋ 考证/兹白、琅玕与三尸神；搜「坎瑞亚历史」→ 日月全事/坎瑞亚历史 ＋ 考证/坎瑞亚的原型与《裴伦埃里》。国别史条目名固定为「日月全事/<国名>历史」（蒙德／璃月／稻妻／须弥／枫丹／纳塔／至冬／坎瑞亚）。
（c）查某个争议。搜「第二王座」→ 考证/尼伯龙根与第二王座 ＋ 原神wiki/天使 ＋ 原神wiki/魔神；搜「倾落伽蓝」→ 原神wiki/倾落伽蓝（3.3 间章），用来核对世界树改写前后的版本差异。流程：先搜争议关键词拿考证条目 → 正文已写明并列保留的各说法、成立条件与存疑待补 → 再回它引用的条目原文复核。
（d）查某本书的典故。搜「裴伦埃里」→ 原神wiki/裴伦埃里（字段「体裁:故事传说」）＋ 考证/坎瑞亚的原型与《裴伦埃里》；搜「逸周书」或「云笈七签」→ 考证/兹白、琅玕与三尸神 ＋ 两条视频条目。书籍条目名就是书名（原神wiki/<书名>）；典籍对照只存在于考证层与视频层——游戏内并不出现「昆仑」二字。

【四、本库的边界】
不含：
· 主线与活动剧情的完整脚本。手册自述「主要内容是各国历史及核心角色的故事，不包括主线、活动剧情」；WIKI 有任务元数据与部分任务文本，但不是流程脚本。
· 实时更新。这是快照式离线库，不含快照之后的版本；手册自陈会出现「新的正式文本对旧的推测没有及时修正」。
· 泄密／解包／内鬼材料。手册明确「绝不将泄密素材作为讨论、分析的根据」。
· 现实考据的一手学术文献：典籍原文靠联网现查（本次已核《逸周书·王会解》《尔雅·释地》），库内不存全文。
· 联网社区内容：NGA、知乎、百度百科对本抓取环境大量 403，考证里的社区表述多数只有标题与摘要，正文未核验。
零覆盖（考证已确认，本次复核）：
· 「魔神名」在 原学视频/ 前缀下 0 命中；「第二王座」0 命中。
· 「稻妻／散兵」：刀匠、雷电五传、倾奇者、一心传、踏鞴砂、国崩、笼钓瓶、流浪者均 0 命中，散兵 1 条（顺带提及）。但「稻妻」二字本身有 14 条命中，全是「日本战国史人名」「九条幕府原型」角度的原型考据，不涉及稻妻游戏内历史剧情——准确说法是「对稻妻游戏内历史（含散兵刀匠事件）零覆盖」，不是「稻妻零覆盖」。
· 实务影响：涉及稻妻剧情史、魔神名、第二王座的问题，本库只能答「查不到」，须另抓来源，不能给结论。

【五、回滚方式（manifest 文件）】
本库按来源分 manifest，第一列即条目 id，第二列是标题＋source 标记（含原站 URL），删除时不必依赖标题匹配：
· D:\ai\gongzuoqu\tools\genshin-kb\manifest.tsv → 原神wiki 19240 条（2.7 MB）
· D:\ai\gongzuoqu\tools\genshin-video-kb\manifest.tsv → 原学视频单集条目
· D:\ai\gongzuoqu\tools\genshin-video-kb\manifest-website.tsv → 日月全事 22 条（source 标记 日月全事(genshinlore.cn):<url>）
· D:\ai\gongzuoqu\tools\genshin-video-kb\manifest-kaozheng.tsv → 考证 10 条（source 标记 考证：本地知识库（原神wiki ＋ 原学视频 ＋ 日月全事））
（提示：这些 tsv 是 UTF-8，用 PowerShell 默认 Get-Content 读会显示乱码，请用 UTF-8 读取或直接开编辑器。）
按 source 精确删除（做法来自 原神wiki/总览与用法）：
DELETE FROM entries WHERE source LIKE '原神wiki(biligame)%';
DELETE FROM fts WHERE id IN (...);
并同时清掉 entries/<id>.md。
二次校验与重放：genshin-kb\backup-kb-before-genshin.sqlite 是导入前备份；genshin-kb 下的 verify.mjs、rebuild-fts.mjs 可校验与重建索引；genshin-video-kb 下的 entries/（单集）、website-entries/（日月全事）、kaozheng-entries/（考证）、summary-entries/（本综述）是各来源的条目 JSON 源文件，可分别用 import-video-kb.mjs、import-website-kb.mjs、import-generic-kb.mjs 重放导入。本次新增的两条综述条目写入 summary-entries/，回滚时按 id 删除并清理 entries/<id>.md。

【六、建议工作流】
1）先在 考证/ 搜争议关键词——已有条目就直接拿分歧地图与评级。
2）没有则搜 日月全事/ 拿世界观主干，注意正文里的【待发现】、脚注与编者注。
3）再搜 原神wiki/ 拿原文（搜专名或原句片段，别搜概念词）——这是判定「游戏内文本明写」的唯一途径。
4）最后搜 原学视频/ 拿原型学与建模材料，只引用它的事实层，不引用它的结论层。
5）任何跨 3.3 世界树改写的引用，先声明改写前／后版本。

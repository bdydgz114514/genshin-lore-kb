# 补证/《日月全事》趣闻与杂谈·动态彩蛋全量补齐

> **ID**：014775a5a818
> **标签**：原神 / 补证 / 外部来源 / 日月全事 / 趣闻与彩蛋
> **来源**：补证：https://genshinlore.cn/interestfacts.html ；https://genshinlore.cn/interestfacts.json

## 摘要

此前抓 genshinlore.cn《趣闻与杂谈》时页面为动态加载、静态快照只渲染出「加载中...」，该条目因此未收录任何具体彩蛋；本次以无头浏览器渲染 DOM 并直取数据接口 interestfacts.json，补上该栏目的全部实际条目并修正原条目对缺口成因的判断。

## 正文

【补了什么缺口】
此前整理《日月全事》网站版时，条目「日月全事/趣闻与杂谈」（website-entries/interestfacts.json，来源 https://genshinlore.cn/interestfacts.html）自己写明了这个缺口：
「该页的趣闻／彩蛋正文在本次拿到的网页快照中并未呈现：正文区域只渲染出『加载中...』三个字——即这一页的条目数据是动态加载的，纯文本快照里只有页面标题、投稿说明与投稿协议，没有任何一条具体的彩蛋或事实内容。」
并据此声明「本条目不记录任何具体的『原神冷知识／彩蛋』」，把根因归档为「这不是『手册没写』，而是『快照未取到』」。
本次把这块补上：既拿到了渲染后的完整 DOM，也定位并直取了该页的数据接口，因此可以给出该栏目的全部实际内容。

【新取得的材料】

■ 材料一：定位到该页的数据接口（出处：https://genshinlore.cn/interestfacts.html 原始 HTML，6488 字符）
页面把条目数据抽成了一个 JSON 接口，由内联脚本渲染。原文关键句（逐字照录）：
  const FACTS_API_URL = 'https://genshinlore.cn/interestfacts.json';
  // 从服务器获取事实数据
  async function fetchFacts() {
      const response = await fetch(FACTS_API_URL);
      if (!response.ok) { throw new Error(`HTTP error! status: ${response.status}`); }
      const facts = await response.json();
      return facts;
  }
渲染函数 renderFact() 把每条渲染成 .fact-item 卡片，字段映射为：id → 「#id」；title → 标题；name（缺省时才回退 author）→ 「作者：」；time（缺省时回退 date）→ 「时间：」；facts → 正文；isittrue → 标题后的 ✓／✗ 标记（源码注释原文：「isittrue 可能是字符串 "true"/"false" 或空字符串」，为空则不出标记）。

■ 材料二：接口实取（出处：https://genshinlore.cn/interestfacts.json）
HTTP 200，Content-Type: application/json，413 字节，UTF-8 无 BOM。返回一个 JSON 数组，长度恰为 2。原文照录：
[
    {
        "id": "1",
        "title": "一个小巧思",
        "name": "Dennis114514",
        "time": "2026-05-06",
        "facts": "虚空劫灰往事书——数世往回皆空虚",
        "isittrue": ""
    },
    {
        "id": "2",
        "title": "标题",
        "name": "作者",
        "time": "2026-05-01",
        "facts": "这里是待填充的内容。",
        "isittrue": ""
    }
]

■ 材料三：无头浏览器渲染 DOM 复核（走法：node fetch-any.mjs "https://genshinlore.cn/interestfacts.html" --only browser --wait 12000，stderr 回报「OK browser」）
dump 出的 DOM 中 class="fact-item" 恰好出现 2 次，原先的「加载中...」占位已消失。渲染结果与接口数据完全一致：
  #1 一个小巧思｜作者：Dennis114514｜时间：2026-05-06｜虚空劫灰往事书——数世往回皆空虚
  #2 标题｜作者：作者｜时间：2026-05-01｜这里是待填充的内容。
两条都**没有** ✓／✗ 标记（isittrue 均为空字符串），即该栏目自己没有对这两条作过真假判定。

■ 材料四：两条条目的性质判定（只依据原文用词，不外加推断）
·#1「一个小巧思」：id=1，作者 Dennis114514，时间 2026-05-06，正文「虚空劫灰往事书——数世往回皆空虚」。这是该栏目唯一一条非占位投稿。注意其正文只有一句话，未注明出处、未说明对应哪条游戏内文本、也未附引用编号——而《日月全事》正文的考据惯例是每条附脚注编号，此处没有。
·#2「标题」：id=2，标题「标题」、作者「作者」、正文「这里是待填充的内容。」——三处都是模板占位字样，日期 2026-05-01 还早于 #1。判定为投稿模板／示例条目，属网站自身的占位数据，不是彩蛋。

【对原结论的影响】
② 修正原结论——原条目的处理立场（不编造彩蛋）正确，但对原因的判断需要改写。
需改写的一句：原条目写「这不是『手册没写』，而是『快照未取到』」——只对了一半。实测结论是：「快照未取到」与「网站本栏本来就只有两条」同时成立。该栏目可公开取到的全部内容就是上述 2 条，其中 1 条还是模板占位。具体改动：
1. 原条目「本条目不记录任何具体的原神冷知识／彩蛋」这一结论继续有效，无需补录任何彩蛋——因为确实没有可录之物。
2. 「手册没写」这一半也部分成立：该栏目不是《日月全事》正文，而是玩家投稿栏，内容量由投稿量决定；目前实质投稿为 1 条。
3. 原条目把根因归结为抓取方式（动态加载），现在应改为「抓取方式已解决，栏目本身内容为空」。
4. 原条目末尾的操作建议「如需该栏目内容，需以浏览器访问 https://genshinlore.cn/interestfacts.html 并等待动态加载后再抓取」——已执行完毕，结论是只有 2 条。
5. 原条目关于证据等级的提醒（「该栏目由玩家投稿、仅代表投稿者个人观点、手册自己声明『不代表网站立场』，因此其条目不能与《日月全事》正文的证据等级等同」）完全成立，并被本次新拿到的接口字段进一步印证：接口专门设有 isittrue 字段用来标注真伪，而现有两条都没有被标注。

【仍然查不到的】
1. 该栏目无历史存档可比对：interestfacts.json 是单一文件、无版本号或修订记录，也无 Wayback 快照可比，因此无法判断此前是否曾有过更多条目而后被删除。
2. #1「虚空劫灰往事书——数世往回皆空虚」未在任何页面给出出处：既未指明它对应哪条游戏内文本（书页／圣遗物／任务台词），也未给出处链接；本次也未能在该站内找到对它的进一步解释。它的真伪无从核验——这正是 isittrue 字段留空的实际后果。
3. 该页无「本页最后更新」时间戳，只有《投稿协议》弹窗底部的「最后更新时间：2026年5月」，因此栏目内容的时效性无法确定：无法判断是该栏目不再维护，还是确实无人投稿。
4. about.html 顶部已声明「网站已暂时停更，内容维持『第3版 苍星圣敕』的内容，新的修改暂不更新」，但未说明该停更是否包含投稿栏目。
